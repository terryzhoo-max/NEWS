## 0. 结论

1. **先改逻辑，再改视觉。** 这个页签现在是一本"进场·止盈·止损·仓位操作手册"，而系统的实际分工是：仓位看执行目标，风险看合规，止损执行看跟踪止盈，MR 只是独立策略信号之一。页面和这套分工相反，只换皮就会把错误的东西做得更像真的。
2. **页面写的规则和引擎实际用的规则不一致**（第 1 节逐条列出）：评分方法、入场门槛、止盈止损、仓位上限都对不上，同一页里也有三四种写法。
3. **验证状态被藏起来了。** MR 三种市场状态的参数都没通过验证（熊市被否，震荡、牛市证据不足），引擎因此把所有"买入"改成"不开新仓"；页面却会写"全仓入场，建议建仓至单标的上限"。
4. **机构级的做法**：把这一页改成"模型说明"（Model Card）。页面上的每个阈值都从引擎实际使用的配置读出，不在 HTML / JS 里写死；先说清用途、边界和验证状态，再讲评分怎么算；用"这只标的今天为什么是 72 分"的评分拆解，取代手动下拉的计算器。
5. 需要你定 5 件事（第 6 节），其中最重要的是第 2 条：止盈、止损、熔断、仓位公式这几块是删除，还是先隐藏。

## 2. 重构原则（机构级、可商用的标准）

参照模型风险管理对"模型文档"的通行要求（例如美联储 SR 11-7：用途、方法、假设、局限、验证、监控），落到这一页就是六条：

1. **单一事实来源**：页面上的每个阈值、权重、门槛都从引擎实际使用的配置读出，HTML / JS 里不再写死数字。规则说明就是引擎的投影，改参数时页面自动跟着变。
2. **职责边界写在最前面**：这一页只回答"信号怎么算、验证到哪一步"。仓位、风险、止损执行只放链接，不放数字。
3. **验证状态前置**：没通过验证的模型，页头第一眼就能看到；新开仓关闭时，页面不出现任何"入场 / 建仓"措辞。
4. **可复现**：每个数字都带参数版本、数据截至日和引擎指纹（接口已有 `source_config_hash` / `source_model_hash`）。
5. **解释重于试算**：用"某只标的今天为什么是这个分数"的评分拆解取代手动计算器，读引擎的真实结果。
6. **视觉按通用约束「界面风格」**：专业克制的金融终端风格；红涨绿跌只表示涨跌；不用 emoji、渐变、毛玻璃、发光；圆角三档（6 / 2 / 0）；等宽数字；每个数字带数据时间。

| 顺序 | 条件 | 研究信号 |
|---|---|---|
| 0 | 关键指标缺失或非数值 | error |
| 1 | 相对成本价回撤 ≥ 止损幅度 | stop_loss（只是研究信号，不触发卖出） |
| 2 | RSI ≥ 卖出阈值 | sell |
| 3 | 收盘 ≥ MA20 且 %B > 0.6 | sell_half |
| 4 | 评分 < 门槛 × 0.75 | sell_weak |
| 5 | 市场状态为崩盘 | no_entry |
| 6 | 牛市且评分 < 门槛 | hold |
| 7 | 趋势条件满足，且 RSI ≤ 买入阈值或 BIAS ≤ 买入阈值，且评分 ≥ 门槛 | buy |
| 8 | 参数未通过验证（`allow_new_entries = false`） | buy 改为 no_entry |

趋势条件：熊市收盘 > MA×0.95，震荡 > MA，牛市 > MA×1.02。

## 4. 视觉规格

- **页头**：一条紧凑状态栏。标签都用 `ac_tokens.css` 现有的标签类：验证状态"被否"用 fail，"证据不足"用 warn；"新开仓关闭"用 block 实底加文字；"研究信号 · 不执行"用 info。
- **研究信号标签**：buy / sell 等一律用中性描边加中文（"研究·买入""研究·卖出"），不用红绿，以免读成交易指令。红绿只留给真实涨跌（比如 A 区的 20 日涨幅）。
- **评分构成条**：100 分按七项权重分段，用单一中性色加分隔线，不用彩虹色；当前门槛画一条细竖线并标数字。
- **评分拆解**：七行横条，轨道是满分，填充是得分，右侧依次是"得分 / 满分 · 原始值"；总分行和门槛差（"距门槛 +12 / −5"）单独一行。
- **表格**：表头小字次要色，数字列右对齐、等宽，单元格圆角 0，悬停只变底色；当前市场状态那一列用浅底高亮，不换颜色。
- **字体与数字**：分数取整，分项保留 1 位小数，指标保留 2 位；缺数据显示 "--"，不用默认数字顶替。
- **中文化**：去掉 BULL MODE、TARGET 1 / 2、TRAILING STOP、FORCED EXIT、FACTOR 等英文标签；市场状态写"牛 / 震荡 / 熊 / 崩盘"。
- **去掉**：58 处 emoji、渐变、发光、内联样式和色值、"重新识别"按钮，以及"✨""自动匹配最优参数"这类宣传性文字。
- **状态**：加载中、部分缺失、不可用统一用 `.ac-state-*`；接口失败时显示原因和数据时间，不显示旧数字。
- **手机 375**：页头标签自动换行；A、B、C 三张表改成竖排卡片；评分拆解条形占满宽度；不出现横向滚动。
- **可访问性**：标的选择支持键盘操作；分项条带文字数值，不只靠长度表达；正文与暗底的对比度达到 WCAG AA。

## 10. 决定（2026-11-26 22:1x 美中，用户授权"以专业科学决策"）

决定前补查了一条证据：计算器打开页面就会用 HTML 里的默认档位自动算分。七项默认值合计 57 分（"动量 Z 分"那个下拉框根本不参与计分），页面打开后又自动同步市场状态。牛市时门槛 60、半仓线 51，页面不需要任何输入就会显示"半仓观察：建议建仓上限的 50%"；震荡、熊市时显示"不入场，建议观望"。另外，执行总览里的"信号评分"按钮直接链到这个页签；状态面板里的门槛用了 `?? 65` 默认数字（违反"缺数据显示 --、不用默认数字"）。

| # | 事项 | 决定 | 理由 |
|---|---|---|---|
| 1 | 页签去留 | **A**：第 3 轮时并入「均值回归」页签，作为"模型说明"折叠块 | 与第 3 轮"每个策略页签只留信号、验证状态、一个证据块"一致；其他策略都没有单独的规则页签 |
| 2 | 止盈、止损、熔断、持仓警告评分、仓位公式 | **A + C**：页面内容直接删除（记为固定规则例外，同第 1 轮海外页做法），原位置留一行"已停用"说明和三个链接；相关 JS 代码先保留，第 5 轮复查时再删 | 这些是第二套仓位 / 止损规则，引擎也不执行；它们是写死的静态文字，没有后台依赖，先隐藏观察 4 周得不到任何信息。隐藏优先原则保护的是可能有依赖的模块，这里不适用 |
| 3 | 计算器 | **A**：下线；第 3 轮换成读引擎真实结果的"评分拆解" | 手动下拉复现不了引擎的连续曲线，还有一个不参与计分的输入；默认值会自动生成建议 |
| 4 | 时机 | **拆开做**：违规与误导内容的"止血"（M1，纯前端）现在就做；结构、规格接口、评分拆解、视觉（M2–M5）仍跟第 3 轮 + V3，按 11-23 的决定放在 P1 之后 | 默认就会出现的"建仓"建议，与固定规则 1–3 和你定的"超标期零买入"直接冲突，而且从执行总览一点就到。M1 不是视觉轮，性质和批次 1 的仓位措辞统一相同，不违反 11-23 的暂缓决定。它只改 `strategy.html` 本页签和 `strategy.js`，和一键导入 C1、决定记录 O3 / O4 / O6 都没有文件重叠 |
| 5 | 因子映射曲线 | **暂不做**，登记为可选待办；MR 任一市场状态通过验证后再评估 | 模型还没通过验证，给它做更精细的解释投入产出低；B 区的公式表已经够用 |
