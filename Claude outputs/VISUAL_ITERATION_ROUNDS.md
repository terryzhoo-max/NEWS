## 1. 视觉规范（每轮都先读；建议并入 `SITE_SLIMMING_ROUNDS.md` 通用约束「界面风格」）

```
【视觉规范 · 全站】
- 风格：专业克制的金融终端（参照 Linear 的简洁）；数字一眼可扫；红涨绿跌
- 不用：emoji、渐变背景、重阴影、发光、毛玻璃、大圆角（圆角只用 --dc-radius 6px 或 2px 两档）、闪烁动画
- 颜色：只引用 static/css/ac_tokens.css 的变量；模块 CSS / JS / 内联样式里不再出现色值
  - 涨跌色 --mkt-up / --mkt-down 只表示涨跌；状态色 --status-* 只表示状态，不得互相借用
  - 阻断 / 否决 / 止损已触发：--status-block（洋红）实底 + 左侧 3px 粗线 + 文字标签；状态不靠颜色单独表达
- 数字：等宽数字（JetBrains Mono 或 font-variant-numeric: tabular-nums），右对齐；百分比、金额统一小数位；缺数据显示 "--"，不用默认数字顶替
- 每个数字带数据时间（"数据截至 MM-DD" / "美股收盘 · MM-DD" 等，已有的写法不改）
- 背景读数（JCS / AIAE / ERP / 海外 / 利率）用中性色，不用红绿暗示好坏，不出现仓位数字和"买入 / 观望 / 清仓"措辞
- 图表：统一走共用图表主题（V0 新建），不在各文件里写颜色
- 文案：中文为主；去掉英文副标题和 emoji；接口返回的文案里的 emoji 前端不显示（接口不改）
- 隐藏模块（各 *_modules.json 中 enabled=false）不做视觉处理
- 改了 JS / CSS，同步升页面引用的版本号
【视觉轮的边界】
- 只改视觉与展示文案；接口、字段、口径、判定、数字都不变。确需改的（例如发现第二个仓位数字），单独列出、单独提交
- 每步前后截图（1440 宽 + 375 宽），存 D:\FIONA\alphacore_baselines\<日期>_<轮次>\，关键数字写进方案
- 每个提交前后做 5 项核对，结论必须不变
- 测试：用 .cjs 锁住"不出现 emoji / 色值 / 渐变 / 仓位措辞"，新测试对改前代码失败
```
